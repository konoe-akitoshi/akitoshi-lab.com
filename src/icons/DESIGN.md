# Akitoshi Lab. アイコン デザイン指示書

`src/icons/` のアイコンを描く・直す・依頼するときの指示書。人に頼むときも AI に頼むときも、この文書をそのまま渡す。
（`README.md` は使い方と技術仕様の要約。デザインの判断はこちらに従う）

---

## 1. 目的と使われる場面

- **使う場所**: `/links`。名刺の QR コードから開かれる、スマートフォン前提のページ。
- **見る人**: 名刺を受け取った人。日本語を読まない人も含む。ページには文字のラベルを置かないので、意味はアイコンが担う。
- **表示の条件**
  - サイズ: 主に 28px。補助として 20px（コピーなど）でも使う。
  - 解像度: スマートフォンの 2〜3 倍の高解像度表示。
  - 色: 白背景に `#374151`（gray-700）。
  - 描画方式: CSS マスクで描くので、使える色は 1 色だけ。形だけで伝える。
- **隣に並ぶもの**: アイコンの右には値（メールアドレス・コールサイン・ハンドル名）が並ぶ。アイコンは「その値が何か」を一目で示す役割を持つ。

## 2. 各アイコンが伝える情報

| アイコン | 1 番目に伝えること | 2 番目に伝えること |
|---|---|---|
| `mail-personal` | メールである | ——（基本形なので印を付けない。個人であることは値のドメインで示す。7.2 参照） |
| `mail-university` | メールである | 大学のアドレスである |
| `radio` | アマチュア無線（のコールサイン）である | — |
| SNS（`linkedin` など） | どのサービスか | — |
| UI（`copy` / `check` / `arrow-outward` / `person-add`） | 押すと何が起きるか、何が起きたか | — |

- **同じ種類のものは同じ骨格にする**: メール 2 つは同じ骨格（同じ外形）を共有し、「同じ仲間」に見えるようにする。
- **違いは 28px で判別できること**: 2 つの違いは、細部ではなく 28px で判別できる差として表す。
- **広すぎる記号を避ける**: 「無線」全般や「放送」と区別がつかない記号（携帯の基地局・Wi-Fi に見えるもの）は避ける。

### 3.1 Flex らしさ（必須）

- **直線と直角を拒む**
  - 長い辺は外側にわずかに膨らませる（swelling）。目安は 24 に対して 0.25〜0.4。
  - 平行な 2 辺は、対称に膨らませる。
  - 斜めの線や脚も、まっすぐにせずわずかに弧を描かせる（Evaluation2 の道路を参照）。
- **膨らみは内側の余白のため**: 外へ押し出す力が働いているように描く。内側の余白が広がり、太くても重たく見えない。
- **角は squircle**: 円弧ではなく、ハンドルを長めにしたベジェで回す。
- **線端は丸く、丸い部品は正円**。
- **「自由だけれど合理的」**: グリッドに厳密には従わず、見た目の補正で整える。ただし構成の論理（対称性・軸・繰り返し）は保つ。
- **人の手の温かみ**: 機械的に整いすぎた幾何学ではなく、自然物や人体の曲線を思わせる柔らかさを出す。

### 3.2 やってはいけないこと

- **直線とまっすぐな斜線だけで構成する**: 一般的なアイコンセットと見分けがつかない。
- **立体的にする、ノイズを増やす**: 影、奥行き、細かい部品の積み重ね。
- **大きな塗りの塊**: このセットは線が主役。塗りは小さな閉じた部品（目安 3×3 以下）に限る。
- **読みやすさのために個性を捨てる**: 判別しやすさと Flex らしさは両立させる。どちらか一方を満たすだけでは不合格。
- **既存アイコンの模倣**: Lucide・Material などの形をなぞらない。

## 4. 技術仕様

- **キャンバス**: `viewBox="0 0 24 24"`。余白は 2 で、描画範囲は 2〜22。
- **キーライン**: 形に応じて次の 4 種類に合わせる。

| キーライン | 範囲 |
|---|---|
| 円 | 中心 (12, 12)、半径 10 |
| 正方形 | 3〜21 |
| 横長 | x 2〜22 / y 4〜20 |
| 縦長 | x 4〜20 / y 2〜22 |

- **線**
  - `fill="none"`、`stroke="currentColor"`、`stroke-width="2"`。
  - `stroke-linecap` / `stroke-linejoin` はどちらも `round`。
  - 線は中心で描くので、パスはキーラインから 1 内側に置く。線端の丸みまで含めて 2〜22 に収める。
- **塗り**: 小さな閉じた部品だけ `fill="currentColor"` を使ってよい。
- **マスク**: `<mask>` を使うときは `<mask stroke="none">` にする。マスク内の図形は、ルートの線の指定を引き継いで太ってしまう。

## 5. セットとしての一貫性

- **線の密度**: 1 アイコンあたりの線の本数と、内側の余白の量を揃える。1 つだけ混んでいたり、1 つだけ空いていたりしない。
- **見た目の大きさ**: 円は四角より小さく見えるので、キーラインで補正する。並べて目を細めたときに、大きさと濃さが揃って見えること。
- **角の丸みの比率**: 外形の角の丸みは、外形の短辺の 20〜30% を目安に揃える。
- **SNS ロゴ**: ロゴとして認識できる特徴は崩さない。そのうえで、線幅・角・膨らみをこのスタイルに揃える。

## 6. 進め方と評価

1. **コンセプトを出す**: アイコンごとに、比喩の案を 3 つ以上、言葉と簡単なラフで出す。2 章の「1 番目・2 番目に伝えること」をどう満たすかも書く。
2. **絞り込む**: 有力な 1〜2 案を描く。
3. **評価する**: 次の項目をすべて確認する。
   - [ ] **シルエットテスト**: 内側を塗りつぶした外形だけで、何のアイコンか分かる。
   - [ ] **28px / 20px テスト**: 高解像度表示で、2 番目に伝えることまで読める。
   - [ ] **目を細めるテスト**: ぼかして見ても、ペア（メール 2 つ）の区別がつく。
   - [ ] **Flex 比較**: 3 章の見本画像と並べて、同じ仲間に見える。
   - [ ] **セット比較**: `src/icons/` の全アイコンと並べて、密度・大きさ・角が揃って見える。
4. **報告する**: 選んだ案、捨てた案とその理由、評価シートの画像（96 / 28 / 20px と Flex 見本の並置）。

## 7. 決定事項と根拠

### 7.1 アイコンと文字の関係

Nielsen Norman Group の [Icon Usability](https://www.nngroup.com/articles/icon-usability/) は、次の 2 点を指摘している。

- 誰にでも通じるアイコンは、家・印刷・虫眼鏡などごく一部しかない。
- そのため、アイコンには常に文字のラベルを添えるべき。

/links ではラベルを置かないが、各行の**値そのもの（メールアドレス・コールサイン・ハンドル名）が文字の役割を果たす**。

アイコンの役割は、その値が「何の種類か」を一瞬で伝えることにある。値を読めば意味が確定するので、アイコンは**誤読されないこと**を最優先にする。その場で意味を新しく覚えてもらう必要がある記号は使わない。

### 7.2 個人メールと大学メール：封筒の角を開けて、家と角帽を置く

- **共通の骨格**: 横長の封筒。右下の角を開け、そこに記号を置く。
- **個人メール**: 家。
- **大学メール**: 角帽。

**経緯**

最初は「個人は印なし、大学だけに角帽」とした。理由は次の 3 つ。

- 「個人」を表す共通の記号がない。
- 家の記号は「自宅」と読まれるおそれがある。
- 要素が少ないほうが読みやすい。

しかし試作を並べた結果、オーナーが「角を開けた封筒＋家 / 角帽」の案（p2-house / u1-cap）を選んだので、これを採用する。

**根拠**

- **2 つのメールが同じ構成になる**: 両方に記号があるので、「封筒＋種類を示す記号」という対称の作りになる。どちらが基本形かを見る人が推測しなくて済む。
- **家は「自宅 / Home」に対応する**: vCard や連絡先アプリには、メールを「自宅（Home）」と「勤務先（Work）」に分ける区分がある。個人メールを「自宅」の側に置くのは、この区分と合っている。
- **値でも補われる**: 値のドメイン（`akitoshi-lab.com` / `uec.ac.jp`）を見れば、誤読があっても意味が確定する。

**描き方の条件**

- **記号は線で直接置く**: 塗りの円のバッジは使わない。28px で潰れるため。
- **封筒の角を開ける**: 封筒の外形は右下の角を開けた線にする。開けた端と記号の間は、パスの間隔で 3 以上空ける。
- **記号は右下に置く**: 封筒の開けた角（右下）に置き、右端は x 21 に揃える。28px で家・角帽として読める大きさを保つ。
- **家と角帽は描き方を揃え、形は記号らしい比率にする**: どちらも線で囲む形にし、内側を空ける。右端と見た目の重さは揃えるが、縦横比はそれぞれの記号に合わせる。
  - 家: 縦長（x 14〜21 / y 13.1〜20.75）。
  - 角帽: 横長（x 12.75〜21 / y 13.6〜19.6）。
- **角帽の形**: 板は横長で平たいひし形（幅：高さ ≒ 2.75：1）にし、線で描く。その下に、浅く広い器を下げる。家の枠に押し込めて縦長にしたり、器を細長くしたりすると、鍵やキノコに見える。
- **封筒の開け方**: 角帽の左端と開けた端の間隔を 3 以上取るため、封筒の下辺は x 約 9.7 まで開ける。2 つのメールで封筒の形を揃えるため、家の側も同じ開け方にする。

### 7.3 アマチュア無線：ハンディ機（トランシーバー）

**根拠**

- **見る人の多くはアマチュア無線をやっていない**: アマチュア無線の国際的な紋章（アンテナ・コイル・アースを組み合わせたひし形）はアマチュア無線家にしか通じない。しかも由来は公式には説明されていない（[contesting.com のスレッド](https://contesting.com/forums/tips/442)）。アマチュア無線家なら、`JL1AVV` という形式を見ただけでコールサインだと分かる。
- **アイコンが伝えるべきなのは、一般の人向けの「無線で人と交信する」こと**。
- **鉄塔やアンテナの記号は誤読されやすい**: 携帯の基地局・放送・Wi-Fi など、インフラを表すのに広く使われているからだ。NN/g が指摘する「同じ記号が場所によって別の意味を持つ」状態になる。
- **ハンディ機は、個人が持つ双方向の無線機**: 「この人に無線で連絡できる」という意味に最も近い。日本のアマチュア無線でも一般的な機材である。

**描き方の条件**

- 電波は**アンテナの先から**出す。本体の横に置くと、スマートフォンのバイブレーションに見える。
- 本体は実物に近い縦長にし、アンテナは本体の上端から伸ばす。

### 7.4 作り直す範囲：セット全体

SNS・UI のアイコンも含め、**セット全体を作り直す**。

**根拠**

- 統一されたスタイルは、セットとしての信頼感につながる。
- 今の SNS・UI アイコンは急いで描いた下書きで、Flex らしさ（3.1）を満たしていない。これを基準に「揃える」と、新しいアイコンの質も下書きの水準まで下がる。

**作る順番**

1. **基準になるアイコンを先に作る**: 封筒（メール 2 つの共通の骨格）と、UI の `copy`。
2. **基準を確定してから残りを作る**: 基準の線の密度・角・膨らみを確定し、それに合わせて残りを作る。

## 8. 確定したセットのパラメータ

封筒と `copy` を基準として作り、次の値で確定した。新しいアイコンもこれに合わせる。

| 項目 | 値 |
|---|---|
| 外形の角の丸み | 外形の短辺の 22%（パスの中心で測る）。25% では Flex と並べたとき膨らみすぎに見えた。Instagram のように元の形が丸いものは 30% まで |
| 角の曲線 | squircle。ベジェのハンドルの長さは角の半径の 0.78 倍（円なら 0.552） |
| 辺の膨らみ | 辺の長さ × 0.022。0.22〜0.40 の範囲に収める。長さ 4 未満の辺は膨らませない。平行な辺は対称に膨らませる |
| 長い斜線 | 0.25〜0.4 だけ弓なりにする（チェック、矢印の軸、X・Zenn の帯など） |
| 内側の余白 | 外形と内側の要素は、パスの間隔で 3 以上空ける（線の太さを除いて 1 以上の隙間） |
| 線の密度 | 基本は「外形＋内側の要素 1 つ」。1 アイコンあたり 3〜4 本まで |
| 塗り | LinkedIn と Instagram の点（半径 約 1.2）だけ |

既知の妥協点:

- **線の太さ**: 線幅 2 は、Flex の見本より約 40% 太い。オーナーが「太め」を指定したため。
- **見た目の重さ**: `check` と `arrow-outward` は外形がないので、他よりも軽く見える。20px の補助的な記号としては許容している。
- **無線の電波**: 試作品（r2-handheld）の構図を採用し、電波は本体の右上から出している。7.3 の「アンテナの先から出す」とは違うが、本体の横からは離してあるので、バイブレーションには見えない。
